This fifth release candidate adds original file exchange in encrypted Agent chats, restores Agent reply text selection, and embeds the Hagency Client libraries directly in Desktop. It retains the question cards, execution recovery and integrated macOS hosting improvements from rc.4.

- Attach documents in an Agent conversation and ask the Agent to process them. With tools enabled by the resource owner, Codex can receive the original file in its room workspace and return generated files as encrypted Matrix attachments in the same conversation. Each file is limited to 8 MiB. Sending has a persistent delivery receipt, so uncertain results can be checked without creating duplicate attachments.
- PDF and text attachments can also be read through bounded room-history pages. Long documents are paginated, and encrypted attachments are verified and decrypted with the Agent's Matrix device.
- Agent reply text can be selected and copied in both folded and expanded replies, including formatted content.
- File upload previews fit smaller windows and remain visible above the native browser on macOS. Dismissing the preview restores the same browser page and scroll position.
- The Client runtime now builds as in-tree libraries inside Desktop; its old standalone UI has been removed. Desktop and the integrated macOS owner daemon use the same source revision.

- Agent questions appear as cards below the message that started the run, with choices and text answers. A message can show questions from several Agents. MCP tool approvals and skill-installation approval prompts are refused by this question channel, and Agent accounts cannot answer another Agent's questions.
- Questions in one turn share a ten-minute waiting budget, including opening the encrypted device, retries and answer verification. A slow device or network request cannot extend the question wait beyond that budget.
- Question cards recover their final state after hosting restarts or interrupted requests. An answer is shown as accepted only after it has been delivered back to the running Agent; unanswered cards expire locally even while the network is stalled.
- Desktop retries encrypted cards that could not initially be decrypted when room or device keys arrive. Successful retries appear immediately, and signing out prevents an older account session from updating the current session's cards.
- Long Codex turns stay active while tools are working, and a completed turn's answer is retained when a command is still running.
- Hosting is managed inside **Agent → Hosting**. Desktop and its background daemon use one registered owner resource directory per account on each computer. The daemon can keep the resource pool available after Desktop quits. The separate Hagency Hosting installer is no longer needed.
- Interrupted Agent calls no longer occupy the entire remaining allowance. All Agents count known consumption instead of the call's reservation. A call whose process is confirmed stopped closes at its known consumption, and later usage reports can still add to that amount. **Missing usage counts as zero, so the ledger can understate provider usage and a run can exceed its allowance.**
- A shared message whose previous attempt is proven never to have started can be retried automatically, up to three times, on servers advertising `shared-demand-retry-v1`. Retries retain the same message and queue position. A lost acknowledgement is reconciled through the original request; an attempt that may have executed is not automatically run again. Older servers keep the evidence-only recovery behavior.
- Running Agents have bounded retries for transient authorization checks and can retry an activity renewal with its original request ID. Revocation ends the run immediately. More precise diagnostics distinguish failed authorization stages; these changes do not establish credential refresh as the cause of every interrupted run.
- Background hosting raises its macOS open-file limit, prioritizes unfinished message recovery, bounds provider-report refresh and shutdown, and reuses Agent device credentials across restarts to avoid unnecessary Matrix logins.
- Encrypted room history retains bounded pagination, event deduplication, long-message handling and malformed-event recovery. Codex controls when to compact a room-history thread. The Windows WebView2 reader, window-focus and divider improvements from rc.2 remain included.

Install **Hagency Desktop** for chat, Agent management and macOS resource hosting. Provider accounts and coding tools must be configured on the execution machine. Server-side recovery improvements require a compatible Hagency server; this installer does not update the server or its trusted-proxy configuration.

This RC includes macOS Apple Silicon and Windows x64 installers. Windows background resource hosting, Windows ARM64, Intel macOS, automatic updates and mobile store packages are not included. Signing status is stated above. Agent question and encrypted-history recovery have offline regression coverage; a real River encrypted-room acceptance run has not been completed. Automated installer checks do not replace a manual Windows 11 acceptance test or production fault-injection coverage of every recovery path.

The version series remains Hagency 0.5.0, following the inherited Rinx 1.1.x releases. Install this RC manually. The earlier [dependency audit follow-up](https://github.com/hagency-org/hagency-desktop/blob/work/hagency-desktop-local-20261028/dev-vibe/release-0.5.0/assessment.zh.md) remains open.
